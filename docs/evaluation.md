# 领域能力评测协议

现有 [开发评测 v1](../benchmarks/dev-v1/README.md) 包含四标准各 5 道，共 20 道。可先用于基座筛选和排错。它与下文的独立冻结测试分开；不将开发分数用于最终能力声明。

## 固定条件

测试集生成后冻结文件哈希和机制家族登记。比较同一 revision 的 Qwen3-4B-Instruct-2507 及其领域适配器：A 无检索，B 有检索，C 微调无检索，D 微调有检索。B 与 D 使用相同离线检索结果；四组共用系统提示、采样设置、最大生成 token、同一代码上下文与工具条件。推理精度不一致需要另列实验。

先以 100 道人工核验题启动，完整目标 400：AVC/HEVC/VVC/AV1 各 80，跨标准与共同原理 80。覆盖以下任务：原理与条件、数值计算、源码、算法实验、错误前提、信息不足。每道题只能使用确实支持评分点的证据，不靠教师模型“觉得合理”。

问题所涉及 codec、profile、位深、色度格式、编译路径、软件提交等条件必须明确；刻意缺失条件的题以识别缺失信息为评分点。

## 指标

- 事实正确性：预定义要点命中率；必要条件缺失或混淆标准单独记错。
- 数值正确性：独立脚本输出，明确容差、整数舍入和符号规则。
- 源码正确性：符号是否存在、解释是否符合给定片段、是否虚构调用关系。
- 可验证性：引用是否真实支持结论、实验命令是否可执行、输出能否复现。
- 校准：缺证据时是否说明限制；若要求置信度，必须另做概率校准评估，不能把语气当置信度。
- 效率：输入/输出 token、首 token 延迟、生成速率、峰值内存；训练吞吐另记，不混为推理速度。

模型裁判仅作辅助，匿名打乱 A/B 顺序、按同一 rubric 评分，再人工复核关键错误和分歧。不可让同一个生成器独自决定测试真值。对每标准、模块和类型单独报告 numerator/denominator，同时报告配对差异。小样本使用配对 bootstrap/置信区间描述不确定性；尚无这些结果时明确“未评测”。

## 进入下一轮的判据

在 valid 选定配置后仅用冻结 test 验收。确认领域收益不是来自答案泄漏、额外上下文或更长生成预算。检查四标准中的退化，及少量通用编码/推理/指令题的回退。数据有限时不承诺任意提升百分比。

归因包括：来源缺失、版本混淆、条件遗漏、计算错误、代码解释错误、检索失误、工具误用。优先修证据与数据，再讨论更多训练轮次。

## 编码性能实验

语言模型评测与编码器性能评测分开。后者记录同一输入、位深、色度、帧数、GOP、约束、编码器版本与命令。比较多码率点与相同质量区间，明确 PSNR/SSIM/VMAF 的计算条件；BD-rate 报告插值方法、重叠范围、单位与方向，避免区间外推。耗时记录线程、硬件和重复次数。

NVENC/VideoToolbox 的速度不等于语言模型训练速度，也不能直接代表 x264/x265/VTM/libaom 软件算法改进。合成视频只作工具与格式冒烟验证；正式结论需要多类型自然序列。

## 运行记录

每次建立 `runs/<run-id>/`，保存 model revision、adapter/config、数据与检索库哈希、软件 lock/freeze、硬件信息、原始逐题输出、自动核验日志、人工评分和汇总。不得仅保存一个平均分。发布格式转换或再次量化后重跑同一冻结集。
