# 资料收集与版本策略

## 资料层级

标准文本用于确定码流、语义、解码过程与符合性。参考软件用于理解特定版本的实现；工业编码器用于研究搜索、率控、并行、剪枝、SIMD 等实现策略。论文用于解释和讨论，命令行文档用于实验操作。它们的角色分别标注，不能用某个实现的行为替代标准要求。

官方入口：

- [H.264 06/2026](https://www.itu.int/rec/T-REC-H.264-202606-I/en)
- [H.265 01/2026](https://www.itu.int/rec/T-REC-H.265-202601-I/en)
- [H.266 01/2026](https://www.itu.int/rec/T-REC-H.266-202601-I/en)
- [AOMedia AV1 规范入口](https://aomedia.org/specifications/av1/)，其链接指向 [v1.0.0-errata1 发布版](https://github.com/AOMediaCodec/av1-spec/releases/tag/v1.0.0-errata1)。规范仓库的开发分支与发布版应分别标识。

2026 标准文本与最新抓取的参考实现不保证覆盖范围完全一致。数据样本必须注明使用的工具、profile、位深、色度格式和软件版本。JM 19.0 是可获取的历史参考版本，不能称作 2026 版标准的完整实现。

## 文件、代码和索引

`configs/sources.json` 描述意图；`materials/sources.lock.json` 记录真实结果。`INVENTORY.md` 是锁文件的人类可读视图。原文保存在 `materials/raw`；代码保存在 `materials/code`，均属于本地资料库。Git 默认只跟踪索引、脚本、自有文档和配置，避免意外把大量第三方文件推送出去。

文件锁定 SHA-256。Git 锁定完整提交号，并保存实际 origin；允许的镜像显式登记，使用镜像不等于验证其与另一个上游完全同步。重复运行不自动更新上游代码。需要新版本时新增 source id，并保留旧锁定记录；HTTP `--refresh` 只用于有意更换快照，更新后重提取并作废依赖旧哈希的证据。

每次下载检查 HTTP 返回、PDF 文件头/ZIP 结构及非空内容。后续用 PDF 解析器核对页数和封面文本，再视觉抽查封面与公式页。可获取不等于内容经过全面审校：提取文本保持 `extraction_verified: false`，逐证据单元核验后才用于正式样本。

不自动执行第三方构建脚本、测试或二进制；算法实验阶段另行构建并记录工具链。遇到登录、付费或不可访问来源，登记状态和官方入口，先使用其他已验证证据，不绕过访问限制。

## 补充范围

优先补充缺失机制对应的规范条款、参考实现说明、原作者论文、JVET/JCT-VC/JVT 公开提案及 CTC。会议文档编号、修订版、下载页和文件哈希缺一不可。教材和会议视频作为解释材料单独标记。付费教材不从非授权站点批量下载。

测试序列先登记来源，再按实际实验下载少量有明确条件的序列。视频质量比较需要自然内容，合成 testsrc 仅适合工具连通性与格式验证。测试码流不等于训练问答数据。

## 使用条件记录

每个 source 保留版权/许可证入口，所有下载初始标记为 `pending_review`。逐样本训练选择可用的来源，保留 notices；文件可免费阅读不自动等于可公开分发完整原文。代码许可证、模型许可证、教师输出使用条件分别记录。自有私有代码不在本轮资料收集中，也不自动发送到外部模型。

该记录用于保证资料可追溯，不要求每次只读检查都向用户重新请求确认。
