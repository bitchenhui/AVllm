# 第一期：用 AI 辅助训练编解码算法专业模型

更新：2026-11-11（Asia/Shanghai）。主训练机：用户已有 M2 Max、32GB 统一内存、1TB SSD；当前开发机：已检测到 M4 Pro、24GB；可选对照机：用户提供的 Windows、Core Ultra 7 356H、32GB RAM、RTX 5060 Laptop 8GB。家中设备未远程检查，不把用户提供配置标记为实测。

## 目标与比较对象

第一版同时覆盖 AVC、HEVC、VVC、AV1。模型根据标准资料、问题条件、代码片段和实验结果，给出有依据的解释与可执行验证。第一期集中于视频编码算法；音频、RTC、直播链路和直接理解视频画面作为后续模块。

候选为 Qwen3-4B-Instruct-2507 的 MLX 4bit 版本。它是便于复现的候选，不预设其优于所有更新模型。先比较同一模型微调前后的领域表现，再将更强模型作为参考上限。原始模型已经指令训练，报告中不能把“未做领域微调”写成“未经预训练”。

成功依据：减少标准混淆、条件遗漏、计算错误、源码虚构；在指定任务上改善正确率与可验证性。低 loss、回答更长和语气更像专家不能单独作为成功依据。

## 阶段 0：建立并核验资料库（本轮）

输入：官方标准、参考软件、主流实现及训练方法。产物：来源清单、原文、固定提交源码、来源锁、逐页提取文本、代码导航、失败记录。

验收：四个标准 PDF 的封面版本匹配、可解析；每份文件有哈希，源码有完整提交号。获取失败保持 unavailable，不编造本地文件或改用无来源转载。页级文本中的表格与公式待视觉核对，不能直接被视为数值真值。

## 阶段 1：证据单元与独立评测

先制作约 100 个“黄金证据单元”：四个标准各 20 个，共同原理/跨标准约 20 个。每个单元包含：标准及版本、机制和条件、原文页/条款、源码函数/提交、允许推导范围、必要的计算或实验校验。

先按机制或实验家族登记 `split_group` 并分配 train/valid/test，再生成改写题。参考 `configs/curriculum.json` 和 `docs/evaluation.md`。同一原题、同一函数的改写、同一次实验的不同描述归同组；哈希分组只能防显式组泄漏，不能自动发现语义相似问题，需要人工与近重复审查。

最终目标约 400 道冻结测试题：四标准各 80 道，跨标准/共同问题 80 道。先有 100 道已核验题即可做第一轮基线，明确覆盖不足，后续增长测试集需升版本。测试答案不进入训练提示词和样本生成反馈。

验收：每道题有评分点、证据、适用条件，数字可核算；测试集独立冻结且有哈希。不要让同一教师模型生成并独自裁定全部测试题。

## 阶段 2：AI 生成候选与外部校验

先做约 2,000 条候选作为试验规模：四标准各约 400，跨标准约 200，共同原理约 200。可根据实际资料难度调整，不强行填满配额。样本覆盖解释、对比、计算、源码、实验设计、错误前提纠正和信息不足。

流程：证据包 → `prompts/generate.md` → 候选 JSONL → 结构与证据哈希检查 → 脚本/编译/实验校验 → 独立 AI 复核 → 领域抽检 → approved。数值、定点溢出、熵编码状态转换、标准条款等高风险样本逐条审查。其他类型按模块抽样；抽样发现系统错误时整批退回。

“AI 生成”可使用可用的大模型或本地教师：本仓库不绑定供应商，不需要先上传整个仓库，不自动发起付费调用。没有外部依据时教师应返回缺证据状态。生成器、审核器与数值验证器职责不同，两个 AI 一致不构成数学或标准正确性的证明。

样本 metadata 保留，导出给 MLX 的训练文件只包含 messages。训练回答应有简洁推导、条件与来源，避免把冗长且未经验证的推理轨迹当作真值。

## 阶段 3：Mac 小跑与首轮 SFT

用 M2 Max 32GB、MLX-LM、4bit 主体和 LoRA。先用 `configs/mlx-smoke.yaml`：batch 1、最大长度 2048、最后 8 层、100 步。短跑只检查数据模板、峰值内存、吞吐和适配器保存/重载，不宣称能力提升。

通过后使用首轮候选配置 `configs/mlx-sft.yaml`：最后 16 层、rank 16、batch 1、梯度累积 4，先训练约一个数据遍历量。当前 MLX 训练循环的 iters 计数微批次，不能当作 optimizer updates：1600 个 iteration 约处理1600个单样本批次，完成400次参数更新。实际 iters 按审核后的 train 样本数重新计算，并向上取为累积次数的整数倍。学习率先在 1e-5 与 5e-5 的小范围用 valid 比较，避免用 test 挑参。

长代码采用检索后片段输入。2048 token 是首轮资源边界，不是永远的上下文上限；先统计样本真实 token 长度，不可静默截断证据或答案。资源测量后再试 4096，不承诺 32GB 上所有配置都能运行。

保存包版本、配置、模型 revision、数据哈希、随机种子、每步/每 token 耗时、峰值内存、训练与验证日志。默认适配器检查点不等于完整优化器和随机状态，恢复适配器不能声称精确续训；需按已安装版本核查。MLX 量化训练与 CUDA NF4 实现不可假定数值等价。

## 阶段 4：四组对照与失败分析

比较：未领域微调、未微调+检索、微调、微调+相同检索。固定模型 revision、推理精度、提示词、生成预算、检索库、检索结果和工具权限。源码题四组都要能获得相同代码上下文，避免把上下文差异误归因于微调。

分别报告每标准、每模块、每任务类型指标，配对分析差异及不确定性；不要只报总体平均数。对严重点评估逐条复核。混合少量通用推理与指令遵循测试，检查领域收益是否伴随退化。错误归因为知识、条件、计算、代码、检索或工具，优先补证据和验证程序，再扩大训练。

## 阶段 5：本地交付与再量化回归

先交付固定模型+适配器的 Mac 版，进行断网推理和内存检查。跨平台 GGUF 路线需要单独验证量化适配器融合、导出和格式支持；不可把 MLX 4bit 目录直接重命名为 GGUF。发布前重跑冻结评测，保留来源通知和适用范围。

## 现在下一步

先从四个标准中各选择一个“预测/变换量化/环路滤波”证据单元，建立总共 20 道人工核验题作为流程演练，同时覆盖四标准。用 `scripts/make_packet.py` 生成有哈希的证据包。完成这一小批的生成与核验后扩到 100 道评测基线，最后才开始首轮微调。资料量不会自动转化为模型能力。

现有机器足以开展阶段 0–3。购机判断放到真实吞吐与内存测量之后；已有 M2 Max 32GB 不必为启动项目再买 Mac mini。
